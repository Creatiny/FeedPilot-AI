## 2. 问题列表

### P0 - 安全问题 (必须修复)

#### P0-1: SQL 注入风险 (scripts/run_skill.py:206-207)

**代码片段**:
```python
sets = ', '.join([f'{k} = ?' for k in data.keys()])
cursor.execute(f'UPDATE customers SET {sets} WHERE id = ? AND owner_open_id = ?', 
              list(data.values()) + [customer_id, user_id])
```

**问题**: 字段名 `data.keys()` 动态拼接进 SQL 语句。虽然有参数化查询，但字段名来自外部输入，攻击者可通过注入恶意字段名执行任意 SQL。

**影响**: 严重 - 可导致数据泄露、篡改、删除。

**修复建议**: 
- 白名单验证字段名: `allowed_fields = {'name', 'phone', 'notes'}`
- 拒绝不在白名单内的字段

---

#### P0-2: 多租户隔离缺失 (scripts/delete_customer.py)

**代码片段**:
```python
def delete_customer(name):
    cursor.execute('DELETE FROM customers WHERE name = ?', (name,))
```

**问题**: 未检查 owner_open_id，任何人可删除任何客户的记录。

**影响**: 严重 - 用户 A 可删除用户 B 的客户数据。

**修复建议**: 
- 添加 owner_open_id 参数
- WHERE 条件增加 `AND owner_open_id = ?`

---

#### P0-3: 多租户隔离缺失 (scripts/list_customers.py)

**代码片段**:
```python
def list_customers():
    cursor.execute('SELECT name, phone, animal_type, scale FROM customers ORDER BY name')
```

**问题**: 未按 owner_open_id 过滤，列出所有客户数据。

**影响**: 严重 - 用户可看到其他用户的客户信息。

**修复建议**: 
- 添加 owner_open_id 参数
- WHERE 条件: `WHERE owner_open_id = ?`

---

#### P0-4: 硬编码用户 ID (scripts/add_customer.py)

**代码片段**:
```python
cursor.execute('''
    INSERT INTO customers (owner_open_id, name, phone, animal_type, scale)
    VALUES (?, ?, ?, ?, ?)
''', ('telegram:7972653610', name, phone, animal_type, scale))
```

**问题**: 硬编码特定用户 ID，所有客户记录归属同一用户。

**影响**: 高 - 多租户功能失效，数据隔离被破坏。

**修复建议**: 
- 改为参数化传入 owner_open_id

### P1 - 架构问题 (建议修复)

#### P1-1: 绕过 Service 层 (scripts/run_skill.py)

**问题**: run_skill.py 直接使用 sqlite3 连接数据库，绕过 Repository 和 Service 层，违反 v1.7 架构设计 (Skill → Service → Repository)。

**影响**: 中 - 维护成本增加，架构一致性被破坏。

**修复建议**: 
- 重构为调用 Service 层接口
- 或明确标记为"简化版 CLI"，不用于生产

---

#### P1-2: 代码重复 (SimplePriceService)

**问题**: SimplePriceService 类在 run_skill.py 和 query_price.py 中重复定义。

**影响**: 中 - 代码冗余，维护困难。

**修复建议**: 
- 合并到单一位置 (如 src/services/simple_service.py)

---

#### P1-3: Skill 接口不一致

**问题**:
- skill.py 要求注入 Service
- query_price.py 可自动初始化 Service
- 其他 skill (formula_cost, nutrition, customer) 要求注入 Service

**影响**: 中 - 调用方式不一致，易出错。

**修复建议**: 
- 统一为 `create_skill(service=None)` 接口
- service=None 时自动初始化

---

#### P1-4: 数据库路径计算不一致

**问题**: 不同文件使用不同方式计算数据库路径:
- auto_add_ingredient.py: `SCRIPT_DIR -> WORKSPACE -> data`
- run_skill.py: `WORKSPACE -> data`
- add_customer.py: 硬编码 `data/feed_sales.db`

**影响**: 中 - 可能导致生产环境路径错误。

**修复建议**: 
- 统一使用 `os.path.join(WORKSPACE, 'data', 'feed_sales.db')`
