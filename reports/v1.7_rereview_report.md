### 2. 统一 Schema 定义

**状态**: ❌ 未修复（严重问题）

**验证结果**:
- `src/database/schema.sql` 定义了完整的多租户 Schema（包含 `owner_open_id`、乐观锁等）
- `scripts/migrate_data_to_db.py` 中的 `create_tables()` 函数使用了**旧版 Schema**，存在以下不一致：

| 表名 | schema.sql | migrate_data_to_db.py | 问题 |
|------|-----------|----------------------|------|
| `formulas` | 包含 `owner_open_id`, `version`, `animal_type`, `stage_type` | 使用 `animal_category`, `stage`, 无 `owner_open_id` | ❌ 字段不匹配 |
| `formula_ingredients` | 使用 `ratio_percent` (CHECK 约束) | 使用 `ratio` (无约束) | ❌ 字段名不一致 |
| `ingredient_prices` | 包含 `owner_open_id`, `ingredient_code`, `version`, `price_date` | 无 `owner_open_id`, 使用 `date` 而非 `price_date` | ❌ 缺少多租户支持 |
| `ingredients` | 无此表（已移除） | 创建此表 | ❌ 多余表 |

**影响**: 迁移脚本无法正确创建与 Schema 一致的表结构，导致数据迁移失败或数据不一致。

**修复建议**:
```python
# migrate_data_to_db.py 需要更新为：
cursor.execute('''
    CREATE TABLE IF NOT EXISTS formulas (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        owner_open_id TEXT NOT NULL,
        name TEXT NOT NULL,
        animal_type TEXT,
        stage_type TEXT NOT NULL,
        weight_range TEXT,
        notes TEXT,
        version INTEGER DEFAULT 1,
        created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
        updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
        UNIQUE(owner_open_id, name)
    )
''')
```

### P0 安全性问题（2 个）
